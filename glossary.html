Glossary

Every term behind a ? button, in plain language.

Basics

Model

A recipe that turns what we know about a person (the features) into a guess about something we want to know (the target).

The three models in this activity were already fitted to the data. You explain how each one makes its guesses; you don't build or change the models.

Feature

One piece of information the model uses, such as age, BMI or waist size.

Each dataset has 4–10 features. The data dictionary on the Data & files page lists them with their units.

Target

The value the model tries to predict: fasting glucose (mg/dL), systolic blood pressure (mmHg) or lung function, FEV₁ (mL).

Always show the target's units next to predictions so viewers know what the number means.

Prediction

The model's guess of the target for one person.

A prediction is not a measurement. Comparing it with the person's observed value shows how far off the model is.

Regression

Predicting a number (like blood pressure), rather than a category (like yes/no).

All three models here are regression models: each predicts a number in the target's units.

Example person

One of five real survey participants per dataset, chosen in advance so every student's app offers the same people. Not a student, and not made up.

Example people 1–3 have a low, a typical and a high outcome; 4 is the one the forest's trees disagree on most; 5 is the one they agree on most. Because every app has the same five, a reviewer can ask for "Blood pressure → Example person 2" in anyone's app.

Checking a model

Training data

The people the model learned from: 80% of each dataset.

Every row in the CSVs has a split column that says train or validation. A model usually looks better on its own training data than on new people.

Validation data

The other 20% of people. The models never learned from them, so they show how well a model does on new people.

In boosting, we also use validation data to choose when to stop. Because we used it to make that choice, its error is slightly optimistic, so we call it a validation result, not a test result.

Test result

An error measured on data that was never used for any decision, including choosing when to stop. This activity has no separate test set.

So say "lowest validation error", not "test error", when you describe the stopping round.

Residual

What's left over: the actual value minus the prediction. Positive means the model guessed too low.

Example (illustrative): actual 130 mmHg, predicted 124 mmHg → residual +6 mmHg.

RMSE (root mean squared error)

A typical size of the model's mistakes, in the target's units. Lower is better.

Square every residual, average them, then take the square root. Big mistakes count extra. Only compare RMSE within one dataset: 20 mg/dL and 20 mmHg are different things.

Overfitting

When a model keeps getting better on its training data but worse on new people, because it is memorising noise.

In boosting, overfitting shows up as training error still falling while validation error has stopped falling or is rising.

Linear regression

Linear regression

A model that predicts by adding up a fixed amount per unit of each feature, like a recipe of weights.

It draws the best straight-line (or flat-surface) fit through the training data. It can't bend, which is easy to explain and sometimes wrong.

Coefficient

How much the prediction changes for one more unit of a feature, holding the other features fixed.

Example (illustrative): a coefficient of +0.5 mmHg per year means two people who differ by 10 years of age, and nothing else, get predictions 5 mmHg apart. Coefficients have units, so you can't compare raw coefficients across features.

Starting point (baseline)

The prediction for the training average: the place every push starts from.

It is supplied as linear.baseline. It is not the intercept: the intercept is the prediction when every feature is 0 (age 0, BMI 0…), which describes nobody.

Intercept

The prediction when every feature equals 0. Usually not meaningful, so don't use it as the starting point.

Starting point = intercept + Σ coefficient × training average.

Push (contribution)

How much one feature moves this person's prediction up or down from the starting point.

Push = coefficient × (this person's value − training average). Starting point + all pushes = prediction. A person who is exactly average on a feature gets a push of 0 from it.

One person vs overall importance

One person's biggest push only tells you about that person. A feature can push one person a lot and most people very little.

For an "in general" comparison, use the typical effect (coefficient × standard deviation), not one person's pushes and not raw coefficients.

Typical effect

Coefficient × the feature's standard deviation: how much the prediction moves for a typical difference between people.

Supplied as linear.typical_effect_per_sd for numeric features. It puts features with different units on a fair footing.

Reference group

For a category such as ethnicity, the group the 0/1 columns are compared with. For blood pressure it is Non-Hispanic White.

Pushes are still measured from the training average mix, so even the reference group gets a small push. Show sex and ethnicity as one menu each, not as separate on/off switches.

Association, not cause

The models show patterns in survey data. They don't show what would happen if someone changed a value.

Say "people with higher BMI tend to have higher predictions", not "lowering your BMI would lower your blood pressure".

Random forest

Decision tree

A model that asks a series of yes/no questions ("Is age ≤ 45?") and gives the average outcome of the training people who ended up in the same place.

Each final group is called a leaf. A tree's prediction can only take a few values, one per leaf, so its responses come in steps.

Random forest

Many decision trees, each a little different, whose guesses are averaged.

The supplied forest has 100 trees. Its prediction is the average of all 100 tree guesses, so it always stays within the range of outcomes seen in training.

Bootstrap sample

Each tree learns from its own random draw of the training people, picked with replacement, so some people appear twice and others not at all.

On average, each tree sees about 63% of the distinct training people. The supplied field bootstrap_unique_training_rows gives the exact count per tree.

Random feature choice

At each question, a tree may only choose from a random handful of the features. This makes the trees differ even more.

The supplied forest tries √(number of features) at each split: 2 of 5 for glucose, 3 of 10 for blood pressure, 2 of 4 for lung function (field features_tried_per_split).

Disagreement (not confidence)

How far apart the trees' guesses are for one person. It is not a confidence or prediction interval.

Trees learned from overlapping data, so their spread isn't a calibrated measure of how wrong the forest might be. Call it disagreement between trees.

Partial forest

The average of only some of the trees, for example the first 10 of 100. Label it, so viewers don't mistake it for the forest's prediction.

Use the trees in their fixed, supplied order so everyone's running averages match.

Gradient boosting

Gradient boosting

A model built one small tree at a time. Each new tree corrects part of the errors left by the trees before it.

The supplied model has 500 rounds of depth-3 trees with learning rate 0.1. Round 0 is the training average.

Round

One step of boosting: one new tree is added. After round m, the model has m trees.

Round 0 means no trees yet: every person gets the training average.

Correction

What one new tree adds to (or subtracts from) a person's prediction in that round.

Prediction after round m = prediction after round m−1 + correction m. The supplied corrections already include the learning rate, so don't multiply by it again.

Learning rate

How much of each new tree's suggestion is used, here 0.1 (10%). Small steps are slower but more careful.

A different learning rate needs a separately trained model. The optional 0.02 comparison is supplied; scaling the 0.1 numbers doesn't reproduce it.

Stopping round

How many rounds to keep. A good choice is near where validation error is lowest, not where training error is lowest.

Training error keeps falling as trees are added, even after the model has started fitting noise.

Publishing

Public link

A web address anyone can open without signing in or asking for access.

Check by opening it in a private or incognito window.

GitHub backup

Your code saved in your GitHub repository. It only counts once you've pushed; saving on your laptop isn't enough.

Commit and push whenever a section starts working, and again before you submit.

Commit ID (SHA)

The unique code for one saved version of your repository, like 3f2c1ab….

Run git rev-parse HEAD, or copy it from the latest commit on your repository's GitHub page.

Static site

A website made only of files (HTML, CSS, JavaScript, data) that the browser runs. GitHub Pages hosts static sites; it can't run Python.

The GitHub Pages starter is static: it reads the supplied JSON files in the browser.

Supplied model outputs

JSON files with every number your app needs (predictions, pushes, tree guesses, boosting rounds), already computed and checked.

Use these instead of training models yourself, so every student explains the same models. Field guide: outputs/SCHEMA.md.
