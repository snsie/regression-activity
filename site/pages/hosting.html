Publish & back up

You need both: a public link {{help public-link}} that anyone can open, and your code backed up on GitHub {{help github-backup}}. Do this before class; it takes 15–20 minutes.

Both are required

A GitHub repository alone isn't a hosted app, and a hosted app alone isn't a backup. This applies whichever host you use.

2. Put the starter on GitHub

  1. Download and unzip the starter from Data & files.
  2. On GitHub, create a new public repository (for example explain-the-model). Don't add a README; the starter has one.
  3. In the starter folder, run: 
    git init -b main
git add .
git commit -m "Starter"
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
    No git on your computer?

    On your new repository's page, click uploading an existing file and drag in everything from the starter folder, including the data and outputs folders. Then click Commit changes.

3. Publish

Route A: GitHub Pages
  1. On your repository, open Settings → Pages.
  2. Under Source, choose Deploy from a branch, then branch main and folder / (root). Click Save.
  3. After 1–2 minutes your link is https://<username>.github.io/<repo>/.

To try it on your computer first, run python -m http.server 8000 in the folder and open http://localhost:8000. Opening index.html directly won't load the data.

Route B: Streamlit Community Cloud
  1. Go to share.streamlit.io and sign in with GitHub.
  2. Click Create app, then pick your repository, branch main and file streamlit_app.py.
  3. Click Deploy. Every package your app imports must be listed in requirements.txt.

To try it on your computer first: uv run --with streamlit,pandas,numpy streamlit run streamlit_app.py

4. Check it like a reviewer

  • Open your link in a private or incognito window. It must load without signing in.
  • Switch datasets in all three sections.
  • Use each section as a stranger would, without your own explanations. Does it teach its learning objective on its own?
  • Put your link at the top of README.md, then commit and push.

5. Back up as you go

Commit and push whenever a section starts working, and again after your final checks. Saving on your laptop, or a local commit, is not a backup until it's pushed.

git add .
git commit -m "Forest section works"
git push

Never commit passwords, tokens or API keys.

6. Before you submit

  • Push your final code, then check that your public link shows it. Hosts can take a minute or two to update.
  • Check that README.md starts with your public app link and a link to each section.
  • Submit your repository link on Canvas. After that, don't change your app during evaluation unless your instructor approves a fix.

Troubleshooting

My GitHub Pages link shows "404"

Wait two minutes. Check that Pages is set to branch main, folder / (root), and that index.html is at the top of the repository, not inside a subfolder.

The page loads, but no data appears

Check that the outputs folder was uploaded, and that your code uses relative paths like outputs/glucose.json (no leading slash).

Streamlit says "ModuleNotFoundError"

Add the missing package to requirements.txt, commit and push. Streamlit redeploys automatically.

Nothing works and time is running out

Switch to the other route. Both use the same data and the same rules, so your work carries over. Tell your instructor if your link breaks during evaluation.
